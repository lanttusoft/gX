# gX — audio subsystem

Status: **reference** — what ships today, how it is wired, and the queued
ideas (including the parked SID-flavor work).

## Layout

| Piece | Source | Role |
|---|---|---|
| Device + registry | `src/audio.{h,c}` | `InitAudioDevice` (miniaudio/PulseAudio via raylib), the string-keyed sound registry (lazily loaded, procedural by default), 3D positional sources, the reverb, the mixer buses, music transport |
| Demo synth | `src/audio/synth.{h,c}`, `synth_schema.c` | general chip-flavored instrument: 8 voices, sine/square(+PWM)/saw/tri/noise/wavetable, per-voice filter (the shared TPT core), LFO, 2-op FM (4 routings), delay, arp, 16-step sequencer, 8-slot patch bank, JSON presets |
| OPX | `src/audio/opx.{h,c}` | 8-operator **phase-modulation FM** engine: per-op ratio/level/detune/feedback/ADSR, a fixed data-driven algorithm table (8 routings), offline-testable render core |
| PAD | `src/audio/pad.{h,c}` | layered **ensemble pad** engine: 3 detuned saw/tri layers per voice with independent slow drift LFOs, long ADSR, per-voice resonant filter (the shared TPT core) with its own slow LFO, a stereo ensemble chorus and a width control over the layer pans |
| SFX pool | `src/audio/sfx.{h,c}` | procedural one-shot effects (thud/clack/metal/arc/click), 4 copies per variant, 3D-positioned, rate-limited; used by the physics sandbox impacts and the toolgun |
| Filter core + master filter | `src/audio/filter.{h,c}` | the shared **TPT/ZDF state-variable filter** (LP/HP/BP, full 0..1 cutoff range — no Chamberlin `2*sin` saturation) and the optional **master filter** on the final mix, kept at the mixed-processor chain *tail* as the engines attach lazily; off by default, persisted with the settings, scriptable via `Audio_*` |
| Tests | `synth_tests.c`, `opx_tests.c`, `pad_tests.c`, `sfx_tests.c` | offline render cores — no audio device needed (`--test-only`) |
| Surfaces | `src/scripting/tour/tour_synth.cpp`, `tour_opx.cpp`, `tour_pad.cpp`, `tour_audio.cpp`, `src/scene/synthvis.c`, `resources/script/synth/synth.as`, `resources/script/audio/opx_pad_demo.as` | the shell tour APIs for the engines/audio, the playable synthvis scene, the synth instrument script and the OPX/PAD ambient demo (self-tested by the scripting gate) |
| Tools | `src/tools/synth/wavetable_editor.cpp` | wavetable authoring panel (`--wavetable-editor`) |

## Wiring conventions

- **Offline core first**: every engine renders through `gX_*_Render(samples,
  frames)` (stereo interleaved float, additive), which the raylib
  mixed-processor adapter and the unit tests share. Device-free tests are the
  admission gate for a new engine.
- **Lazy mixer attach**: engines attach their processor on the first sounding
  note and detach ~1 s after silence (`gX_*_Update` from `gX_Audio_Update`),
  so a silent engine costs no audio-thread work.
- **Muted by default**: `GX_SYNTH_MUTE` / `GX_OPX_MUTE` / `GX_PAD_MUTE`
  (default 1) keep interactive and audit runs quiet while voices, the scope
  and the offline core keep running. `GX_AUDIO_MUTE=1` gates every gX play
  path (registry, one-shots, 3D, SFX, music) for audits; `--disableAudio`
  skips the device entirely.
- **Mixer buses**: `GX_AUDIO_BUS_MASTER/MUSIC/SFX/SYNTH`
  (`gX_Audio_BusSetVolume`). Instruments (demo synth, OPX, PAD) ride the
  synth bus; user volumes persist with the settings file and the pause menu
  carries the Master/Music/Effects/Synth sliders.
- **No assets**: tones, wavetables (the three shipped `.f32` fixtures are
  generated by `scripts/gen_wavetables.py`), engines and effects are
  procedural. New resource files need a provenance entry (see
  `ai_policy.md`, `asset_clearance.md`).
- **Fixed render rate**: engines run at 48 kHz; raylib converts file sounds
  to the device rate but exposes no device-rate getter, so the processor
  path assumes 48 kHz (revisit if a device ever runs elsewhere).

## Queued ideas (author-proposed, unscheduled)

1. **SID-flavor chip extras** *(parked 2026-10-15)* — the demo synth already
   reads SID-ish (naive PWM/saw/tri/noise through a resonant multimode
   filter, per-voice ADSR). Missing chip traits worth a small slice: ring
   modulation (voice 3 → voice 1), oscillator hard sync, combined waveforms
   (tri+pulse, saw+pulse, pulse+noise AND), shared-filter routing with
   per-voice taps, and optional 6581-style filter saturation plus envelope
   rate quantization. Ring mod + sync are the two that change the character
   most.
2. **Master low/high-pass filter** *(idea 2026-10-15; the engine landed
   2026-10-16)* — `src/audio/filter.{h,c}` provides the shared **TPT/ZDF
   SVF** (full-range cutoff, stable at any resonance) and the **master
   filter** on the final mix (tail-kept, persisted with the settings,
   `Audio_SetMasterFilter` in the shell). The demo synth's and PAD's
   per-voice filters were **migrated onto the same core** (2026-10-16), so
   every cutoff in every engine now spans the full range — note the voicing
   shift: cutoffs above ~0.17 used to collapse onto one ~8 kHz filter, so
   existing patches read brighter/more open at the top. Remaining
   follow-ups:
   - **Pause-menu filter controls** (enable/type/cutoff/resonance) — the
     settings fields and the live sync already exist; only the layout is
     parked.
   - **Per-bus filters** (music/SFX/synth) and an OPX output filter (FM
     brightness taming; DX7 had none, TX81Z/OPL do) remain optional.
3. **PAD follow-ups** — an ImGui pad editor (layers/chorus/filter)
   *(presets, tour bindings and the demo landed 2026-10-16)*, per-layer
   waveform select (pulse/noise/wavetable beyond saw/tri), unison voice
   allocation.
4. **OPX follow-ups** — a DX-style 8-op editor panel *(presets, tour
   bindings and the demo landed 2026-10-16)*, per-op keyboard
   scaling/velocity sensitivity, a global pitch EG, LFOs, DX7 `.syx` import
   (user-supplied data only).
5. **Scene ambience beds** — procedural wind/water/machine drones with a
   scene opt-in (title/sandbox/battle), reusing the SFX pool's generation
   style.
6. **Generative music** — sequencer + patch bank playing chord/bass/drum
   beds per scene (no assets).
7. **Sample playback / MIDI** — a streamed sample instrument (the tour's
   `Sound_PlayFile` binding is still deferred) and MIDI-keyboard input
   routing into the engines.

## Gates

- `--test-only` runs the offline suites (`gX_Tests_Synth`, `gX_Tests_OPX`,
  `gX_Tests_Pad`, `gX_Tests_AudioSFX`).
- `GX_AUDIO_MUTE=1` is set by the sandbox gates (`physics-editor-check`,
  `ui-audit`) so procedural SFX never leak into a capture run; the synth
  gates use `GX_SYNTH_MUTE=1`.
- The lean gate measures the whole audio cluster (engines are size-favored
  where they are event-rate only; DSP cores stay on the default tier).
