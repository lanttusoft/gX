# Release hardening

Four source-only gates cover the release mechanics that the runtime gates do
not: reproducible builds, an SBOM, a credential scan and a deterministic
archive. None of them change the shipped renderer; the Release payload only
gains the commit-date stamp described below.

| Check | Command | Tier |
| --- | --- | --- |
| Credential/private-path scan | `make secret-scan` | quick, inside `make check` / `check-fast` |
| SPDX 2.3 SBOM freshness | `make sbom-check` | quick, inside `make check` / `check-fast` |
| Two-tree Release build | `make reproducible-check` | tooling |
| Deterministic archive + extraction | `make release-archive-check` | tooling |

## Reproducible builds

Release builds are reproducible across extraction paths and build times:

- `cmake/CompilerFlags.cmake` applies
  `-ffile-prefix-map=${CMAKE_SOURCE_DIR}=.` in Release, so `__FILE__` and
  debug prefixes do not leak the builder's checkout path;
- the teletext build stamp uses `GX_BUILD_DATE` from the commit date
  (`git log -1 --date=iso-strict`) instead of `__DATE__` / `__TIME__`;
- build directories are never embedded.

`make reproducible-check` runs `git archive HEAD` twice, extracts both trees
under `build/reproducible-check/`, builds each with `./build.sh Release` and
`SOURCE_DATE_EPOCH` set to the commit time, and compares:

- the two archive byte streams;
- `build/gX_build` (and `build/libgx_engine_core.so` when present) SHA-256.

Toolchain changes (compiler version, libc, linker) still change bytes; the
gate pins path/time leakage, not a cross-machine toolchain. Run it on the
release machine before packaging. The two builds take the usual Release build
time; the script keeps its logs in `build/reproducible-check/`.

## Evidence stamps

Optional Lean/C evidence stamps ([lean_proofs.md](lean_proofs.md#evidence-freshness-stamps))
are written to explicit scratch/evidence paths. Their UTC timestamps and Git
metadata are sidecars only; they are not embedded in the binary, SBOM or
deterministic source archive.

## SBOM

`sbom/gX.spdx.json` is the committed SPDX 2.3 document, generated by
`scripts/sbom.py` from the package table in that script plus the vendored
header versions. It lists:

- gX itself (`GPL-3.0-or-later`, version from `readme.txt`);
- raylib and its bundled `stb`/`cgltf`/`miniaudio`/`glad`/GLFW components;
- Dear ImGui, rlImGui, AngelScript and raymath;
- adapted renderer formulations (three.js GTAO, FXAA 3.11, IQ, Ashima,
  ACES/AgX, NTSC/CRT);
- the optional ODE system dependency and the separate Lean proof pin;
- the two CC0 fonts and the CC BY 4.0 skybox.

The document is deterministic (sorted keys, fixed namespace and the release
date from `CHANGELOG.md`), so the gate compares it byte-for-byte:

```bash
python3 scripts/sbom.py --write   # after changing a vendored version/license
python3 scripts/sbom.py --check   # gate
```

The release archive helper ships the same file; the archive check extracts a
copy and runs `--check` inside it.

## Secret scan

`scripts/secret_scan.py` scans **tracked text files only** (`git ls-files`;
a directory walk without Git metadata is the archive fallback). It skips
files over 4 MiB and binary blobs, so build trees, wine prefixes and
screenshots can never produce findings. Rules:

- PEM private-key blocks, GitHub/AWS/Google/Slack/Stripe tokens and JWTs;
- quoted API-key/secret/token/password assignments (`generic-secret`), with
  placeholder values (`example`, `changeme`, `your_`, `<...>`, one repeated
  character) ignored;
- private release paths (private `/mnt` checkout roots, home `git/` or
  `projects/` directories, and the private release tree name).

Findings print the path, line and rule only; the matched value is never
echoed. An inline `pragma: allowlist secret`, `gitleaks:allow` or
`noqa: secret` marker suppresses a deliberate fixture line. The rule tests
are in `scripts/test_secret_scan.py` and run in both admission tiers.

## Deterministic archive

`scripts/release_archive.py` replaces the manual archive step:

```bash
# release candidate (clean worktree required)
python3 scripts/release_archive.py --out build/artifacts

# owner signing (GPG_TTY keeps the pinentry on the terminal)
GPG_TTY=$(tty) python3 scripts/release_archive.py \
  --out build/artifacts --sign F7C08EEFF255A7D815456256DF847784DE0123EF
```

Outputs:

- `gX-v<version>.tar.gz` from `git archive` with a `gX-v<version>/` prefix;
- `gX-v<version>.tar.gz.sha256` in `sha256sum -c` format;
- with `--sign`, detached ASCII-armored signatures for the archive and the
  sidecar (`.asc`).

`make release-archive-check` builds the archive twice, requires identical
bytes, extracts one copy, verifies the version and runs the SBOM check inside
the extracted tree. `git archive` writes zeroed gzip mtimes, so the bytes are
stable across runs; the gate also rejects `.git` metadata and build trees in
the member list.

## Limitations

- Reproducibility is claimed for the Linux Release build with a fixed
  toolchain, not for MinGW or a different compiler version.
- The SBOM is a source inventory, not a vulnerability scan; Dependabot and
  GitHub secret scanning remain the hosted controls.
- `--sign` needs the owner's private key and pinentry; the gate never signs.
